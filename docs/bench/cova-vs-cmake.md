## How to read this

**Cold builds are at parity.** With an empty output directory Cova
and CMake + Ninja run the same number of compiler processes; Cova no
longer scans every translation unit before compiling it, because the
compiler's own depfile proves the closure (see `docs/CORRECTNESS.md`
§5). CMake's column still includes its configure step, and Cova still
pays a full capability probe for a fresh `COVA_HOME`.

**No-change builds are now stat-driven.** Cova keeps the content hashes
the state file recorded and validates them with one `stat` per file, so
a build with nothing to do no longer re-reads the closure. A `touch`
without a content change does not rebuild, and a content change that
keeps the size is still detected. The guarantee that remains stronger
than Ninja's mtime check: the recorded inputs and outputs are verified,
not merely timestamped.

**The shared cache is consulted after the record, not before.** An
unchanged action is answered by the incremental record, which is cheaper
than restoring files that are already correct. `--offline` changes
nothing on a no-change build, which is the point: the cache is for work
that is missing, not for work that is present.

**What Cova wins.** The shared artifact cache has no Ninja equivalent:
deleting `target/` restores objects instead of recompiling them, and the
restore carries the depfiles so the restored tree is warm immediately.
CLI startup is on the same order as `ninja --version` and far below the
PRD's 100 ms target.

## Method

- Every sample is a fresh process invocation, timed around the child
  process only (`sync()` runs before the clock starts).
- Cova cold runs remove `target/`, `cova.lock` and `cova-toolchain.lock`
  and use a fresh `COVA_HOME`, so neither the shared artifact cache nor
  a cached probe can turn a cold build into a restore. CMake cold runs
  remove `build/` and pay a full configure.
- Warm runs reuse the tree each tool left behind. `noop` and `one-file`
  are primed with a real build first.
- The single-file scenario rewrites one unit's source before each sample,
  which Cova sees through its content hash and Ninja through the mtime.
- Cova runs with its shared cache enabled (the default). `plan` uses
  `cova build --dry-run`, which still loads the project and resolves the
  toolchain, against `ninja -n`, which reuses CMake's generated graph.
- Timing noise is real on a desktop; read the range, not just the median.
